# 与一号位沟通 · 第 2 课：在谈判桌上建立信任与边界

> source：HA7CH 一线企业沟通经验＋《麦肯锡方法》中“事实建立可信度、聚焦关键驱动因素”的可用部分｜类型：讲授+情境演练｜前置：最好完成第 1 课

## 一句话本质

**专业不是把技术讲得很难，而是让一号位清楚知道：什么能做、为什么可信、哪里需要验证、下一步怎样行动。**

## 1. 首次沟通少问，按意愿逐步深入

老板还没有确认你的价值时，不要立刻丢一份长问卷。首次交流先解决：

1. 他为什么现在关注 AI；
2. 哪个结果或流程最值得改变；
3. 是否愿意进入下一步验证。

没有明确意愿时，先展示你对业务的理解、证据和确定性。问卷是意愿确认后的诊断工具，不是获客工具。

## 2. 按老板的 AI 认知阶段切换讲法

- 没真正使用过 AI：解释 AI 怎样作用到企业，为什么已有 SaaS+AI 后仍可能需要人进场。
- 已经用过 Codex、Claude Code：少做科普，直接讲团队的 FDE 方法、行业理解和交付证据。

面向老板尽量用中文业务语言。不要只说 FDE、AI Native、workflow、agent；解释谁进入企业、改哪个流程、产生什么结果。

## 3. 技术难度不要传递成“做不了”

技术人员讲“数据复杂、准确率不够、接口不稳定”，心里往往想表达“这么难我也能做”；老板听到的却是“风险很大、做不了”。

不要隐藏风险，改用这个顺序：

> 结论 → 能达到的结果 → 判断证据 → 边界 → 验证动作

例如：

> 单据字段提取可以做，我们已有相似案例。异常格式需要用贵公司的真实样本验证，所以不建议直接接管全流程。先拿一批历史单据跑一轮，一周内就能判断是否达到上线标准。

能力边界分四类：

- 确定能做：讲结果、证据、范围和下一步；
- 原理可行但需验证：讲验证条件和停止标准；
- 当前团队做不了：坦诚说明，必要时推荐其他方向；
- 市场普遍未解决：建议客户继续比较，用同数据、同指标测试。

## 4. 竞品出现时，不攻击

不要说 SaaS、垂类 Agent 或其他团队都不专业。即使批评有事实依据，也可能让客户觉得你在否定他的判断。

先确认竞品解决的是不是同一个业务环节，再讲双方在行业理解、现场方式、定制程度、交付证据上的真实差异。没有脱离场景的绝对优势或劣势，只有某个特征是否适配这个客户。

面对“别人保证百分之百能做”，可以建议客户让所有团队使用同一批真实数据、同一指标做小验证。你不靠攻击获胜，靠事实。

## 5. 犹豫与 Pushback

老板说“我再考虑一下”，先区分他在犹豫价值、信任、价格、时机、方案，还是内部阻力。不同疑虑不能用同一句催单话术。

专业 pushback 不是把“不行”说得更客气，而是：

1. 承认对方希望达到的目标；
2. 给出你的专业判断；
3. 说明约束和影响；
4. 提供可选择方案；
5. 锁定下一决定。

保持平等，不低三下四，也不教育客户。不是所有客户都必须吃下来，停止纠缠不适配的合作也是专业。

## 实操：三轮对话

Read `references/executive-communication/scenarios.md`，选择“技术讲难了”或“老板拿竞品比较”。只向学生展示公开信息：

1. 学生给第一次回复；
2. 导师按隐藏信息继续施压；
3. 学生再次处理；
4. Read rubric 反馈；
5. 给一版可真实说出口的示范；
6. 只确定下一次要改的一个动作。

## 本节小结

- 少问但问关键问题；
- 用业务语言匹配对方认知阶段；
- 技术风险要转成边界和验证动作；
- 不诋毁竞品，用事实比较适配度；
- pushback 的目标是守住边界后继续推进决策。
